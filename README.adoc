= USB UPS Simulator for Arduino Leonardo + W5500

A USB HID UPS simulator for NUT/Nut-ups testing.

The reference firmware runs on Arduino Leonardo/ATmega32U4, presents a USB HID Power Device to the system under test, and uses a W5500 shield as a separate TCP control plane. Hardware UART (`Serial1`) provides a fallback control path.

== Architecture

[source,text]
----
                  trusted test/control network
                          TCP 5000
                             |
                             v
                    +----------------+
                    | W5500 Ethernet |
                    +-------+--------+
                            | SPI/ICSP
                    +-------+--------+
                    | Arduino        |
                    | Leonardo       |
                    +---+--------+---+
                        |        |
                 USB HID UPS   Serial1
                        |       115200
                        v
                 NUT host under test
----

== Key features

* USB HID Power Device / UPS
* NUT `usbhid-ups` Arduino HID compatibility
* one top-level HID UPS Application collection, including the NUT extension
* W5500 control on TCP port `5000`
* `Serial1` UART control at `115200`
* bounded DHCP attempt with `169.254.42.42/16` fallback
* firmware-enforced arming lease and safe-state recovery
* non-blocking USB interrupt-report attempts with immediate retry on incomplete batches
* atomic handling of AVR state shared with USB control requests
* read-only HID Feature locking
* Python API and `ups-sim` CLI with protocol synchronization/version checks
* host-side `ups-sim-selftest` for USB HID + LAN discovery + command verification
* pinned Arduino toolchain and flash-budget CI

== Supported reference hardware

* Arduino Leonardo or compatible ATmega32U4 native-USB board
* W5500 Ethernet shield with the 2x3 ICSP connector populated

Leonardo SPI comes from the ICSP header. Common UNO-style W5500 shields that do not connect the ICSP header are not directly compatible.

[cols="1,1,3",options="header"]
|===
|Function |Connection |Notes
|W5500 SPI |ICSP |MOSI/MISO/SCK
|W5500 CS |D10 |Reserved for Ethernet
|microSD CS |D4 |Firmware holds HIGH; leave SD unused for commissioning
|UART |D0/D1 |`Serial1`, 115200 baud
|USB HID UPS |Leonardo USB |Connect to NUT/system-under-test host
|===

== Quick start

=== 1. Clone

[source,shell]
----
mkdir -p ~/Arduino/libraries
cd ~/Arduino/libraries
git clone https://github.com/ami3go/USB-UPS-Simulator.git HIDPowerDevice
cd HIDPowerDevice
git switch main
----

=== 2. Install the pinned reference dependencies

[source,shell]
----
arduino-cli core update-index
arduino-cli core install arduino:avr@1.8.8
arduino-cli lib install Ethernet@2.0.2
----

=== 3. Compile and upload

[source,shell]
----
arduino-cli compile --warnings all \
  --fqbn arduino:avr:leonardo \
  ~/Arduino/libraries/HIDPowerDevice/examples/UPS_Simulator_Ethernet

arduino-cli board list
arduino-cli upload \
  --fqbn arduino:avr:leonardo \
  -p /dev/ttyACM0 \
  ~/Arduino/libraries/HIDPowerDevice/examples/UPS_Simulator_Ethernet
----

See link:docs/FLASHING.md[FLASHING.md] for Arduino IDE and bootloader-recovery procedures.

=== Linux notes: installing arduino-cli and serial permissions

If `arduino-cli` is not already installed, the official installer drops a binary into a directory you choose -- no system package or root needed:

[source,shell]
----
mkdir -p ~/bin
curl -fsSL https://raw.githubusercontent.com/arduino/arduino-cli/master/install.sh | BINDIR=~/bin sh
export PATH="$HOME/bin:$PATH"   # add this line to ~/.bashrc or ~/.zshrc to persist it
----

On Linux, `/dev/ttyACM*` is normally owned by `root:dialout` with group-only read/write access. If `arduino-cli upload` fails with:

[source,text]
----
OS error: cannot open port /dev/ttyACM0: Permission denied
----

add your user to the `dialout` group once:

[source,shell]
----
sudo usermod -aG dialout "$USER"
----

Group membership is only picked up by *new* login sessions, so fully log out and back in (or reboot) afterward -- opening a new terminal window inside the same session is not enough. If you cannot log out right away, `sg` runs a single command with `dialout` active immediately:

[source,shell]
----
sg dialout -c "arduino-cli upload --fqbn arduino:avr:leonardo -p /dev/ttyACM0 examples/UPS_Simulator_Ethernet"
----

Uploading to a Leonardo triggers a USB bootloader touch (1200-baud reset), so the port briefly disappears and re-enumerates as a fresh device node. Because of that, a one-off `sudo chmod 666 /dev/ttyACM0` gets silently undone mid-upload -- the `dialout` group membership (or `sg dialout` per command) is the fix that survives the re-enumeration, not a manual `chmod`.

=== 4. Connect

DHCP is attempted first. Fallback:

[source,text]
----
169.254.42.42/16
TCP 5000
----

[source,shell]
----
nc <simulator-ip> 5000
----

New firmware greets immediately with identity and current arm state.

=== 5. Safe first test

[source,text]
----
PING
STATUS?
ARM ON
AC OFF
BATTERY 40
LOAD 65
STATUS?
RESET
----

`ARM ON` defaults to a 120-second firmware lease. Every command refreshes it. `ARM ON <seconds>` accepts `0..3600`; `0` deliberately disables expiry.

== Safety and reliability

The simulator can trigger real NUT shutdown actions, so firmware safety does not depend only on the host controller.

* boot starts disarmed and computes a valid safe HID state before Ethernet/DHCP
* state mutation requires arming
* abandoned armed sessions return to safe state when the lease expires
* `RESET` and `ARM OFF` restore safe online defaults immediately
* newest TCP connection replaces a stale/half-open controller
* DHCP maintenance is not allowed to block an armed fault-injection session
* USB-shared 16-bit values and `PresentStatus` are handled atomically
* read-only HID Features reject host writes
* failed interrupt-report batches remain pending for immediate retry

TCP/5000 has no authentication or encryption. The ARM gate and lease are safety controls, not access controls. Use a point-to-point link, dedicated management/test VLAN, or firewall rules limiting TCP/5000 to authorized controllers. Authentication only in Python/Cockpit cannot secure the raw Arduino listener.

== Python driver

[source,shell]
----
python -m pip install -e ./python-driver
----

UART extra:

[source,shell]
----
python -m pip install -e './python-driver[serial]'
----

Example:

[source,python]
----
from ups_simulator import UpsSimulator

with UpsSimulator.tcp("192.168.1.50") as ups:
    with ups.armed_session(lease_seconds=120):
        ups.set_ac(False)
        ups.set_battery(40)
        ups.set_load(65)
        ups.set_input_voltage(228.5)
        ups.set_output_voltage(230.1)
        print(ups.status())
----

The driver synchronizes connection framing with `PING`, accepts both old delayed and current immediate greeting timing, validates the `v2` firmware identity, and preserves an original test exception if cleanup also fails.

CLI examples:

[source,shell]
----
ups-sim --host 192.168.1.50 status
ups-sim --host 192.168.1.50 arm --lease 120
ups-sim --host 192.168.1.50 ac off
ups-sim --host 192.168.1.50 battery 40
ups-sim --host 192.168.1.50 reset
----

=== Hardware self-test

With Leonardo connected to the PC by USB and W5500 connected to the same LAN:

[source,shell]
----
python -m pip install -e './python-driver[selftest]'
ups-sim-selftest
----

The tool verifies the USB HID Power Device, discovers the Ethernet simulator, checks the disarmed safety gate, exercises the complete v2 command set with read-back validation, and always attempts a final `RESET`. It refuses the OB/LB/shutdown-state portion if it detects a live `upsmon`, unless explicitly overridden.

If the IP is known:

[source,shell]
----
ups-sim-selftest --host 192.168.1.50
----

See link:docs/SELF_TEST.md[the hardware self-test guide] and link:python-driver/README.md[the Python driver manual].

== NUT support

Core fields include battery charge/runtime/voltage, capacity limits, delay Features and `ups.status`.

The extension also exposes:

[source,text]
----
ups.load
input.voltage
output.voltage
ups.delay.start / ups.timer.start
----

`ups.load`, `input.voltage`, and `output.voltage` require *NUT 2.8.5 or later*. Check:

[source,shell]
----
usbhid-ups -V
upsc <ups-name>@localhost
----

See link:docs/NUT_SETUP.md[NUT setup] and link:docs/NUT_VARIABLES.md[NUT variable mapping].

== Full-cycle shutdown testing

If the NUT host may power down, independently power Leonardo + W5500 through a supported external-power input. Keep USB connected so the host sees the HID UPS whenever it is powered. See link:docs/HARDWARE.md[HARDWARE.md].

== Resource budget

Pinned CI reference build:

[source,text]
----
Original UPS example:
  flash 10176 / 28672 bytes (35%)
  RAM     330 / 2560 bytes (12%)

Ethernet/NUT simulator:
  flash 27854 / 28672 bytes (97%)
  RAM    1321 / 2560 bytes (51%)
----

The simulator has 818 bytes of application flash headroom. CI enforces `<= 28160` bytes, preserving at least 512 bytes for future reliability fixes. Rich scenarios, persistence, dashboards and orchestration belong on Python/Linux/Cockpit.

== Known limitations

* `COMMLOST ON` sets a HID flag but does not physically detach USB or guarantee NUT `NOCOMM`.
* host-written start/shutdown/reboot delay values do not yet implement a full countdown/output-power state machine.
* MAC address and USB serial are still compile-time defaults; multi-simulator rigs must give boards unique identities manually.
* raw TCP control has no authentication.

== Hardware validation

CI and emulation do not replace real hardware checks. Before a release, verify Leonardo + W5500 startup/fallback timing, NUT state across MCU reset, NUT 2.8.5+ extended variables, stale-controller takeover, and (if relevant) Windows enumeration as a single UPS/battery device. `ups-sim-selftest` automates the USB discovery and command-path portion of this validation.
